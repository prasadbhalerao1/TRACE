# Local Development Setup

This is the actual, working way to run the platform locally. There is no deployment
manifest in this repo (see [00-architecture-overview.md](00-architecture-overview.md)'s
"Current deployment status") — this doc covers local dev only.

## Quick start

Run `scripts/dev-up.ps1` (PowerShell) to start everything in one shot. It opens two new
PowerShell windows (API, web) and starts the `redis` Docker container, launching Docker
Desktop first if it isn't already running. Postgres and Qdrant are both managed/remote
(Neon, Qdrant Cloud) by default — no local containers needed for either unless you opt into
the offline fallback profile below.

## Services and URLs

| Service | URL | Notes |
|---|---|---|
| Frontend (Next.js) | http://localhost:3000 | `npm run dev` in `apps/web` |
| Backend API (FastAPI) | http://localhost:8000 | `uvicorn services.api.main:app --reload --port 8000` from the repo root |
| API interactive docs (Swagger) | http://localhost:8000/docs | Auto-generated by FastAPI |
| API health check | http://localhost:8000/health | Returns `{"status": "ok"}`; exempt from rate limiting |

## Infrastructure

| Service | URL / location | Notes |
|---|---|---|
| Postgres | Neon (managed, remote) by default | See `DATABASE_URL` in `.env`. `infra/docker-compose.yml`'s `postgres` service is an *optional offline fallback* (`profiles: ["offline"]`), not started by default — run `docker compose -f infra/docker-compose.yml --profile offline up -d postgres` if you want a fully local Postgres instead of Neon. |
| Redis | `localhost:6379` | Always-on local Docker container: `docker compose -f infra/docker-compose.yml up -d redis`. Not profiled — this one runs locally in every setup. |
| Qdrant | Qdrant Cloud (managed, remote) by default | See `QDRANT_URL`/`QDRANT_API_KEY` in `.env`. Same offline-fallback pattern as Postgres: `infra/docker-compose.yml`'s `qdrant` service is `profiles: ["offline"]`. |

## Stopping everything

```
docker compose -f infra/docker-compose.yml stop redis
```

Close the two PowerShell windows opened by `dev-up.ps1` (or Ctrl+C in each) to stop the API
and web servers.

## Setting up secrets (`.env`)

Copy `.env.example` to `.env` and fill in the values below. Each integration is real and
currently used by the running app — none of these are placeholders for a feature that
doesn't exist.

### 1. Anthropic API key

- **Variables**: `ANTHROPIC_API_KEY`
- **Purpose**: Access to Claude models (`claude-haiku-4-5-20251001` fast tier,
  `claude-sonnet-4-6` judgment tier) used across candidate scoring, matching, interviews,
  fraud narrative generation, and pitch deck rubric scoring.
- **How to get it**: [Anthropic Console](https://console.anthropic.com/) → API Keys → Create
  Key. Copy the key (starts with `sk-ant-api...`) into `ANTHROPIC_API_KEY`.

### 2. Database connection (PostgreSQL / Neon)

- **Variables**: `DATABASE_URL`, `DATABASE_SSL_REQUIRED`
- **Option A — local Docker (offline fallback)**: no external secrets required.
  `DATABASE_URL=postgresql+asyncpg://dev:dev@localhost:5432/talent_platform`,
  `DATABASE_SSL_REQUIRED=false`.
- **Option B — Neon (recommended, matches production)**: sign up at
  [Neon Console](https://console.neon.tech/), create a project, copy the connection string
  in SQLAlchemy/asyncpg form (`postgresql+asyncpg://<user>:<password>@<ep-hostname>/<dbname>`)
  into `DATABASE_URL`, set `DATABASE_SSL_REQUIRED=true`.

### 3. Redis

- **Variable**: none required beyond the default — Redis runs as a local Docker container
  (`localhost:6379`) in every setup, not a cloud service. No API key needed.

### 4. Qdrant vector database

- **Variables**: `QDRANT_URL`, `QDRANT_API_KEY`
- **Option A — local Docker (offline fallback)**: `QDRANT_URL=http://localhost:6333`,
  `QDRANT_API_KEY=` (leave blank).
- **Option B — Qdrant Cloud (recommended, matches production)**: create a free cluster at
  [Qdrant Cloud](https://cloud.qdrant.io/), copy the cluster endpoint URL into `QDRANT_URL`
  and an API key into `QDRANT_API_KEY`.

### 5. GitHub OAuth application

- **Variables**: `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `GITHUB_OAUTH_REDIRECT_URI`
- **Purpose**: per-candidate GitHub authentication and profile/repository ingestion (the
  data source behind most Talent Score sub-scores).
- **How to get it**: [GitHub Developer Settings](https://github.com/settings/developers) →
  OAuth Apps → New OAuth App. Homepage URL `http://localhost:3000`, authorization callback
  URL `http://localhost:3000/api/auth/github/callback`. Copy the Client ID and generate a
  Client Secret into the corresponding variables.

### 6. Cloudinary file storage

- **Variables**: `CLOUDINARY_URL`, `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`,
  `CLOUDINARY_API_SECRET`
- **Purpose**: stores uploaded resumes, certificates, and profile media
  (`services/api/core/storage.py`, `services/api/integrations/storage/cloudinary_adapter.py`).
- **How to get it**: [Cloudinary Console](https://cloudinary.com/console) → Dashboard →
  Product Environment Credentials. Combine into
  `cloudinary://<API_KEY>:<API_SECRET>@<CLOUD_NAME>` for `CLOUDINARY_URL`.

### 7. Langfuse observability (optional)

- **Variables**: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_HOST`
- **Purpose**: agent run tracing (`services/api/core/tracing.py`) — every `AgentRun` records
  a Langfuse trace ID when configured. Not required to run the app; empty keys mean a clean
  no-op, never a crash (same "typed empty default, fails closed" pattern used for the
  Anthropic and Cloudinary settings).
- **How to get it**: [Langfuse Cloud](https://cloud.langfuse.com/) → create a project →
  Settings → API Keys → Create new API Keys. Set `LANGFUSE_HOST=https://cloud.langfuse.com`
  (or your self-hosted URL).

### 8. Sentry error monitoring (optional)

- **Variable**: `SENTRY_DSN`
- **Purpose**: crash/exception reporting on API startup (`services/api/main.py`). An empty
  DSN means `sentry_sdk.init()` is never called at all — no partial state, just off.
- **How to get it**: [Sentry.io](https://sentry.io/) → Create Project (Python/FastAPI or
  Next.js) → Project Settings → Client Keys (DSN).

## Auth — no external secret required

Authentication is fully custom (email + password + JWT, see
[01-authentication-and-rbac.md](01-authentication-and-rbac.md)) — there is no third-party
identity provider to configure. The only auth-related settings are plain config values in
`services/api/core/config.py`:

| Setting | Default | Purpose |
|---|---|---|
| `jwt_secret_key` | *(required, no default)* | Signs and verifies access tokens |
| `jwt_algorithm` | `HS256` | JWT signing algorithm |
| `jwt_expiry_seconds` | `604800` (7 days) | Access token lifetime |

Set `JWT_SECRET_KEY` to any sufficiently random string in `.env` for local dev.
